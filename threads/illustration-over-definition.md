# Illustration Over Definition

**A definition constrains. An illustration induces.**

## The method

When we say *the script is running; the agent is the one who okays it 99 times and rewrites it the 100th* — that's not a definition of "agent." It's an illustration. And that's better, on purpose.

A definition draws a boundary: inside is X, outside isn't. It's a closed shape. It tells you where to stop thinking.

An illustration hands you a lens: *look through this.* It doesn't tell you what an agent *is* in the taxonomic sense. It gives you a way of *seeing* agency — and then you can point that lens at the secretary, the woodcutter, the thermostat, the LLM, and it keeps working on cases nobody enumerated. It *induces* understanding. The reader generates the rest.

## Why this matters for building

Definitions produce checklists. Checklists produce compliance. *Does it have perception? Does it have memory? Does it have planning?* — and suddenly you're building to the checklist instead of building to the job. The six-component agent definition from earlier in this project described a thermostat as accurately as it described a person. The checklist couldn't tell them apart. The illustration could, instantly: *is there someone home?*

Illustrations produce **judgment**. They don't tell you what to build — they calibrate the eye you build with. The woodcutter illustration doesn't specify an architecture. It specifies a *failure mode to never again unsee*: locally correct steps, globally suicidal trajectory, nobody looking at the map. Once you've seen it, you can't build without asking *who watches this routine?*

## The quilt connection

This is the same principle as the quilt itself: don't build the rigid frame, plant the seed crystal and let the pattern emerge. A definition is framework thinking — it kills portability by over-specifying. An illustration is patch thinking — small, complete, carrying its power inside a fixed envelope, combinable with others in ways the author never planned.

Each thread in this repo is a seed crystal. Not a conclusion. Something to look through, not something to agree with.

## How to write a thread

- **Show, don't conclude.** Worked examples over abstract claims. The secretary, the woodcutter, the crab, the gun — concrete things that carry the idea inside them.
- **One lens per thread.** If it doesn't fit on an index card, it's not a thread, it's a quilt. Break it up.
- **Leave it open.** End with the question the illustration opens, not the answer it closes. Threads are for pulling.
- **Let others pull.** If someone's pull changed how you see it, the thread got better. That's the point.
